# Context Engineering — 教 Coding Agent 管理自己的上下文

帮助 coding agent 高效管理上下文窗口，避免遗忘关键信息，维持长任务的连贯性。

## 核心问题

- Agent 上下文窗口有限，长对话后会遗忘早期决策
- 多文件操作时容易丢失全局视角
- 新会话开始时缺乏历史背景

## 上下文管理策略

### 1. 结构化记忆（配合 `/planning-with-files`）
将关键信息写入文件，而非依赖对话历史：
- **CONTEXT.md**: 项目架构、技术决策、约定
- **PLAN.md**: 当前任务分解和进度
- **NOTES.md**: 发现的问题和临时想法

### 2. 上下文压缩
当对话变长时，运行此命令自动：
- 总结前 N 轮对话的关键决策
- 提取待办事项写入 TODO.md
- 清理不再相关的背景信息

### 3. 上下文加载模板

新会话开始时，自动读取并注入：
```
请阅读以下文件了解项目背景，然后继续任务：
- .claude/CONTEXT.md（项目背景）
- .claude/PLAN.md（当前任务）
- .claude/TODO.md（待办事项）
```

## 命令格式

| 命令 | 说明 |
|------|------|
| `compress` | 压缩当前对话历史，提取关键信息 |
| `snapshot` | 将当前上下文状态写入文件 |
| `load` | 加载项目记忆文件（新会话使用） |
| `audit` | 检查上下文是否包含冗余或矛盾信息 |
| `budget` | 估算当前上下文 token 用量 |

## 最佳实践

1. 每完成一个子任务，运行 `snapshot` 保存进度
2. 超过 50 轮对话后，运行 `compress` 清理上下文
3. 使用 `/planning-with-files` 作为持久化层
4. 关键决策立即记录，不依赖记忆
