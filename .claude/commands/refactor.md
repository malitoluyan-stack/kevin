# Refactor — 代码重构建议与最佳实践

审查代码，给出重构建议，提升可读性、可维护性和性能。使用 `$ARGUMENTS` 指定文件或范围。

## 命令格式

| 命令 | 说明 |
|------|------|
| `suggest <file>` | 分析并给出重构建议（不修改） |
| `apply <file>` | 执行安全的自动重构 |
| `review <file\|diff>` | 代码评审：bug + 可读性 + 最佳实践 |
| `patterns <dir>` | 识别反模式（重复代码、上帝类、深嵌套等） |
| `complexity <file>` | 计算圈复杂度，标记高复杂度函数 |
| `naming <file>` | 审查命名规范，给出改进建议 |

## 重构原则

- **SOLID**: 单一职责、开闭原则、里氏替换、接口隔离、依赖倒置
- **DRY**: 识别重复代码，提取公共函数
- **KISS**: 复杂逻辑简化，避免过度设计
- **YAGNI**: 删除未使用的代码和功能

## 评审维度

| 维度 | 检查项 |
|------|-------|
| 正确性 | 逻辑错误、边界条件、空指针风险 |
| 可读性 | 命名、注释、函数长度（>20行警告） |
| 性能 | N+1 查询、不必要的循环、内存泄漏 |
| 安全 | 注入风险、权限检查、输入验证 |
| 测试性 | 耦合度、可 mock 性 |

## 输出格式

每个建议标注：**优先级**（High/Med/Low）+ **位置**（file:line）+ **问题** + **改进代码**
